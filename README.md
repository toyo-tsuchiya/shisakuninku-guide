## 集計レポートSSの構成（固定6シート）

シートが増えない設計。週次・月次ともに固定シートに追記または上書きする。

| # | シート名 | タブ色 | 更新方法 | 内容 |
|---|---------|--------|---------|------|
| ① | 週次推移 | 青 | **毎週追記** | 1行/週：実働・製造・製造比率・労務費 |
| ② | 職人別週次 | 水色 | **毎週追記** | 1行/職人×週：職人ごとの週次実績 |
| ③ | 案件進捗 | 緑 | **毎週上書き** | 全案件の現在状態（累計工数・担当者・残日数） |
| ④ | 月次推移 | 黄 | **毎月追記** | 1行/月：KPI（製造比率・平均製品工数・労務費） |
| ⑤ | ブランド別 | 薄黄 | **毎月追記** | 1行/ブランド×月：月内+累計工数・労務費 |
| ⑥ | 企画別 | 紫 | **毎月追記** | 1行/企画×月：誰が・何時間・いつからいつまで |

## 主な関数一覧（WeeklyReport.gs）

### 実行関数

| 関数名 | タイミング | 内容 |
|--------|-----------|------|
| `generateWeeklyReport()` | 毎週木曜 7:00（自動） | 週次レポート更新 |
| `generateMonthlyReport()` | 毎月1日 7:00（自動） | 月次レポート更新（先月分） |
| `generateMonthlyReportForMonth(year, month)` | 手動 | 特定月の月次レポート生成例: `(2026, 5)` |
| `generateWeeklyReportBackfill()` | 手動（過去分遡り） | START_DATE_STRから今日まで週次を一括生成 |

### トリガー設定（初回1回のみ実行）

| 関数名 | 内容 |
|--------|------|
| `setupWeeklyTrigger()` | 毎週木曜 7:00 トリガー設定 |
| `setupMonthlyTrigger()` | 毎月1日 7:00 トリガー設定 |

### デバッグ

| 関数名 | 内容 |
|--------|------|
| `testAccess()` | 日報ログSS・スケジュールSSへのアクセス確認 |
| `debugWeeklyReport()` | 集計期間内のログ一覧・突合チェック |
| `debugUnmatched()` | 未突合製品の類似候補を出力 |

## 費用計算の考え方

| 項目 | 値 | 備考 |
|------|-----|------|
| 分給（日報アプリ） | **42円/分** | 間接労務費込みの概算 |
| 分給（原価表） | **36.8円/分** | 直接労務費のみ（生産管理課が管轄） |
| 間接労務費割合 | 15% | 直接労務時間85%:間接15%として算出 |

日報の労務費（42円/分）は管理用。原価表（生産管理課管轄）への転記時は36.8円/分ベースで算出。

## 製品試作フロー（工程と担当）

```
1. 依頼受領（企画）
2. 内容確認（試作課）
3. 部材選定（試作課）
4. 型紙作成（試作課）
5. モック作成（試作課）
6. 修正（企画+試作）
7. 1stサンプル（試作課）
8. 評価会（関係部署）
9. 2ndサンプル（試作課）
10. 原価算出（試作課）← 日報の累計工数が根拠データになる
11. 指示書作成（試作課）
12. 量産引継ぎ（試作課→現場）
```

原価表は**生産管理課が管轄**。試作課は工数データを提供する役割。

## 突合ロジック（スケジュールSSとの紐付け）

日報の製品名・企画名をスケジュールSSと突合する際の優先順位：

1. 日報の製品名 = スケジュールSSの製品名
2. 日報の製品名 → スケジュールSSの企画名経由で製品名を逆引き
3. 日報の企画名 = スケジュールSSの企画名

突合できない場合は「未紐付け」として集計に含める。
